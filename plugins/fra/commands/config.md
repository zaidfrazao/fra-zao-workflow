---
description: Generate or update the project configuration file for existing projects
allowed-tools: AskUserQuestion, Bash, Read, Write
---

Generate or update the `.claude/project.yaml` configuration file for an existing project.

This command is for projects that were initialized before the configuration system was added, or for regenerating the config if needed.

## Steps

### Step 1: Check Current State

```bash
ls -la .claude/project.yaml 2>/dev/null
```

If config already exists:
> "A configuration file already exists at `.claude/project.yaml`."
>
> "Would you like to:"
> 1. **Update it** - Keep existing values and fill in any missing fields
> 2. **Regenerate it** - Start fresh with new values
> 3. **Cancel** - Keep the existing file as-is

Use `AskUserQuestion` to get their choice.

### Step 2: Gather Project Information

If regenerating or creating new, use `AskUserQuestion` to ask:

1. "What is the name of your project?"
   - Try to pre-fill from package.json, Cargo.toml, go.mod, or directory name

2. "Give a brief one-line description of the project"
   - Try to pre-fill from package.json description if available

3. "What type of project is this?"
   - Options: Web App, API/Backend, CLI Tool, Library/Package, Desktop App, Mobile App, Fullstack

4. "Who will primarily be using Claude Code on this project?"
   - Options:
     - **Technical user** - Comfortable with code, git, and technical terminology
     - **Non-technical user** - Prefers simple explanations and guided workflows

5. "Who is the technical lead for code reviews?" (optional)
   - This is used for @mentions in Lakar comments
   - Can be left blank

6. "What is your Lakar client name?" (optional)
   - Can be left blank if not using Lakar

### Step 3: Detect Build System

Auto-detect the build tool:

```bash
ls package.json 2>/dev/null && echo "DETECTED: npm/node"
ls nx.json 2>/dev/null && echo "DETECTED: nx"
ls pnpm-lock.yaml 2>/dev/null && echo "DETECTED: pnpm"
ls yarn.lock 2>/dev/null && echo "DETECTED: yarn"
ls Cargo.toml 2>/dev/null && echo "DETECTED: cargo/rust"
ls go.mod 2>/dev/null && echo "DETECTED: go"
ls Makefile 2>/dev/null && echo "DETECTED: make"
ls pyproject.toml setup.py requirements.txt 2>/dev/null && echo "DETECTED: python"
```

If multiple detected or unclear, ask the user which to use.

### Step 4: Detect Existing Commands

Try to detect existing build commands from package.json scripts or similar:

```bash
# For Node.js projects
cat package.json 2>/dev/null | grep -A 50 '"scripts"'
```

Use detected scripts to pre-fill build commands where possible.

### Step 5: Create Directory Structure

```bash
mkdir -p .claude
```

### Step 6: Generate Configuration

Create `.claude/project.yaml`:

```yaml
# Claude Code Project Configuration
# Generated by /fra:config

project:
  name: "{project-name}"
  description: "{description}"
  type: {project-type}  # web-app, api, cli, library, desktop-app, mobile-app, fullstack

user:
  mode: {user-mode}  # technical or non-technical

team:
  lead: "{team-lead or empty}"
  lakar_client: "{lakar-team or empty}"

git:
  default_branch: main
  branch_prefixes:
    feature: "feature/"
    bugfix: "fix/"
    hotfix: "hotfix/"
    chore: "chore/"
  merge_strategy: squash
  delete_branch_after_merge: true

build:
  tool: {detected-build-tool}
  commands:
    lint: "{detected or default}"
    typecheck: "{detected or default}"
    build: "{detected or default}"
    test: "{detected or default}"
    dev: "{detected or default}"
  dev_port: 3000

lakar:
  statuses:
    todo: "Todo"
    in_progress: "In Progress"
    in_review: "In Review"
    done: "Done"
    paused: null
    blocked: null

commits:
  types:
    feature: "feat"
    bugfix: "fix"
    refactor: "refactor"
    style: "style"
    docs: "docs"
    test: "test"
    chore: "chore"
  include_scope: false
  footer: |
    🤖 Generated with Claude Code

docs:
  brand_template: {full if UI project, minimal otherwise}
  testing_template: full
```

**Build command defaults by tool:**
- **npm**: `npm run lint`, `npm run typecheck`, `npm run build`, `npm run test`, `npm run dev`
- **yarn**: `yarn lint`, `yarn typecheck`, `yarn build`, `yarn test`, `yarn dev`
- **pnpm**: `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test`, `pnpm dev`
- **nx**: `nx affected -t lint`, `nx affected -t typecheck`, `nx affected -t build`, `nx affected -t test`, `nx serve`
- **cargo**: `cargo clippy`, `cargo check`, `cargo build`, `cargo test`, `cargo run`
- **go**: `golangci-lint run`, `go build`, `go build`, `go test ./...`, `go run .`
- **make**: `make lint`, `make check`, `make build`, `make test`, `make dev`

### Step 7: Update CLAUDE.md (if needed)

Check if CLAUDE.md exists and if it has the Communication Style section (for non-technical users):

```bash
ls CLAUDE.md 2>/dev/null
grep -l "Communication Style" CLAUDE.md 2>/dev/null
```

If user mode is non-technical and CLAUDE.md doesn't have the Communication Style section, offer to add it:

> "Your CLAUDE.md doesn't have the non-technical user communication guidelines. Would you like me to add them?"

If yes, add the Communication Style section to CLAUDE.md:

```markdown
## Communication Style

This project is configured for a non-technical user. Claude should:
- Use simple, everyday language instead of technical jargon
- Explain what's happening in terms of outcomes, not implementation
- Hide complex details unless specifically asked
- Guide through workflows step-by-step
- Translate technical errors into plain language
- Focus on "what" and "why" rather than "how"
```

### Step 8: Update .gitignore (if needed)

Check if .gitignore includes Claude Code artifacts:

```bash
grep -l "playwright-mcp" .gitignore 2>/dev/null
grep -l "changeset" .gitignore 2>/dev/null
```

If not present, offer to add them:

> "Your .gitignore doesn't exclude Claude Code artifacts. Would you like me to add them?"

If yes, append to .gitignore:

```
# Claude Code artifacts
.playwright-mcp/
.changeset/
```

### Step 9: Report Completion

**For technical users:**

---

**Configuration Generated**

Created `.claude/project.yaml` with:
- **Project:** {name} ({type})
- **Build Tool:** {tool}
- **User Mode:** {mode}

**Review and customize:**
- Build commands in `build.commands.*`
- Lakar statuses in `lakar.statuses.*`
- Team settings in `team.*`

The `/zao:` commands will now use these settings.

---

**For non-technical users:**

---

**Configuration Created!**

I've set up the project configuration file. This helps me understand:
- What kind of project this is
- How to run tests and builds
- How to communicate with you

**What's next:**
- The project is ready for the `/zao:` workflow commands
- If you need to change settings later, you can edit `.claude/project.yaml` or run `/fra:config` again

---

## Handling Updates

If updating an existing config (user chose "Update it"):

1. Read the existing `.claude/project.yaml`
2. Identify any missing fields (comparing to the full schema)
3. Only ask questions for missing fields
4. Preserve all existing values
5. Write the updated config

## Important

- Always try to auto-detect values before asking
- Pre-fill answers where possible to reduce user effort
- For updates, preserve existing values - only fill in gaps
- The config file should be valid YAML
- Offer to update CLAUDE.md and .gitignore for completeness
